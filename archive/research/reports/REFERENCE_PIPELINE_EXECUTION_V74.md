The M74 reference pipeline is a prepared implementation for the next research turn. It has not been integrated into the repository or run on scientific data. The accompanying tests use metadata fixtures, fake process objects and fake clocks; they never launch Blender, decode a lunar image, run a solar ray or construct a neural model.

The full 96-unit completed-dataset audit, with at least 95% exact-correspondence pose success, must pass before initialization. The inventory retains all eight original model-selection terrain groups and all 32 generated cameras, including complete independent exclusion reasons and oracle outcomes. Every independently eligible camera is prepared, giving N ≤ 32 reference maps. An eligible camera with a failed oracle pose remains in the case denominator. Groups with no eligible camera remain explicit in metadata. Four distinct eligible terrain groups are needed for the cost pilot; a smaller pilot inventory writes a SHORTFALL receipt before any physical job or child protocol is admitted.

Initialization freezes the complete generated inventory and both physical protocols for every independently eligible reference. The map is the original full scene mesh, identified by the independent audit; its original maximum height remains the coverage ceiling. Preparation receives raw reference geometry only. The generic Sun catalogue has coarse columns computed and fine columns marked uncomputed; no query-specific Sun is added, even as a masked column. The later case producer keeps query depth/pose/labels in scoring archives and exact query Sun in the explicit secondary track, with each actual reference-image Sun supplied separately.

The serial phases are:

1. Prepare one predetermined reference map and measure its complete external child interval, including Blender startup.
2. Extend that pilot to four predetermined, terrain-spread references, reusing the first output. The three-reference fixed cap is `ceil(2 × maximum measured outer pilot time × 3 + dispatch overhead)`.
3. Prepare the remaining N−4 references. Its fixed cap uses the same formula with the maximum external time from all four pilot references and a count of N−4. Previously completed references are never run again.
4. Run the existing `index_solar_reference_assets_v69.py` against exactly all N eligible measured reference archives and their exact prep/lookup protocols.
5. Run the existing `build_solar_eval_data_v69.py`, producing schema70 cases: N eligible cameras × six fixed light pairs = 6N positives, plus 6N matched certified nonoverlap cases retaining both eligible terrain endpoints. The original 32-camera inventory, exclusions and all eight raw groups remain in the manifest; a 31/32-eligible inventory therefore produces 186 positive and 186 negative cases, rather than excluding more cameras or inventing a 32-eligible requirement. Case/scoring files remain covered by their original completion checksum seal.

Every phase reserves its entire fixed allowance from the existing canonical baseline journal `runs/solar-compute-reservations-v67.json`. It uses the original compute ledger and preserves the reservation prefix; failed or incomplete work never receives a refund. The settings ceiling is a limit within the existing remaining baseline budget, not a new allowance. Later physical phases must leave room for both mandatory metadata stages. Teacher extraction, training and matcher comparisons remain separate admissions; the 48-hour/72-hour cumulative research constraints are unchanged.

Each phase has one immutable creation time, publication/dispatch lease and absolute deadline, within the preparation contract's fixed absolute deadline. Expired leases/deadlines cannot be reset by invoking the runner again. The original failed rendering attempts and the live completion's 4 November 13:23:15.913367 UTC cutoff are untouched. This new reference preparation begins only after complete data qualify and receives its own predeclared deadline; it never extends a data-acquisition attempt.

The outer watchdog admits only the existing reference-ray preparation program and the two existing metadata programs. Blender is launched with two threads, a separate process group and `--python-exit-code 3`; its wall/monotonic allowance begins before startup. SIGTERM/SIGINT set a pending flag, so an interruption inside process creation cannot lose the assigned child handle. Cleanup sends SIGTERM, escalates to SIGKILL if needed, and uses bounded waits within reserved cleanup time. Exit zero without a complete, correctly hashed reference sidecar is a failure. A partial stage, prior log, archive or watchdog receipt is preserved and cannot be automatically retried.

All scientific dependencies, executables, raw reference geometry, full scenes, full-data audit and generated physical protocols are pinned. After each completed phase, the next artifact-dependent protocol is prepared, but dispatch stops until its exact bytes, the contract and source closure exist in the supplied published revision. Source hashing is repeated before each child. No publication is automatic. The protocol builder performs metadata preparation only; reference arrays are parsed only after an admitted prep child or by the existing index/case producer. Read-only evidence replay hashes completed archives without parsing their arrays.

Integration requires copying the four implementation files into the repository, reviewing the prepared settings template, and running repository checks before publication. No central evaluation file or live rendering dependency needs editing by this package. Apply the included minimal solar_eval_data_eligibility_v74.patch to the existing case producer: it preserves all raw selection-group metadata and permits zero-eligible selection groups while retaining the original training-group gate.
