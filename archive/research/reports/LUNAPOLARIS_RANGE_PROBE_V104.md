# LunaPolaris transfer data availability

Sequences 01, 07 and 10 record repeat traversals in the same University of Luxembourg LunaLab layout. The comparison uses ceiling lights, a low spotlight, and a low spotlight plus a rover headlight. The same facility was used for SPICE-HL3. A second collection gives a physical lighting and sensor comparison while remaining one site. The spotlight is a near-field source, with elevation varying by position, so this does not validate a parallel Sun model. [Dataset paper](https://orbilu.uni.lu/handle/10993/67131) · [Stanford benchmark, LunaPolaris section](https://arxiv.org/html/2610.30774v1#S3.SS3.SSS4)

The official Zenodo API identifies all four records as release 1.0.0. It supplies full-file MD5 identities. The audit verified the complete small sidecar bytes against those identities and separately recorded SHA-256. The database MD5 values identify the published full objects. The audit checked the requested pages, not the full database hashes.

Each inventory lists 17 topics, including native rectified stereo images, left/right CameraInfo, two motion-capture pose streams for the ZED2 marker, a Livox LiDAR, and static and dynamic transforms. The separate 4,046-byte stereo calibration sidecar is published at MD5 `b80161a348720252f5d5335cc0af56d9`, SHA-256 `4d6aff2c8f6109aa7a2ad756e1f9824bb7597dc28b92f6339eda78571fb51bff`. It reports 640×360 calibration and includes raw nonzero distortion, stereo rectification and projection. Check the recorded rectified CameraInfo and physical baseline before treating these values as the bag-image projection model. [Calibration record](https://doi.org/10.5281/zenodo.16728838)

Each database serves exact 4,096-byte pages through HTTP 206 with a declared full size matching the publisher. The SQLite schema declares `messages(id PRIMARY KEY, topic_id, timestamp, data BLOB)` and a covering `timestamp_idx` with timestamp plus row ID. The audit only follows schema and index pages. It caps reads at twelve pages per sequence and records exact Content-Range and SHA-256 for each page. No image, LiDAR, transform or motion-capture payload is requested. The server supplied no ETag on the probed pages, so a future extraction should retain exact range-level digests and versioned record identity, and report the absence of whole-archive verification. [SQLite file format](https://www.sqlite.org/fileformat2.html)

The one-second midpoint index windows returned 553, 521 and 547 timestamp–row ID records. These windows used six, six and seven pages including each schema page, for 77,824 database bytes across all three recordings.

Next, verify the bag CameraInfo, static transforms, source capture time and motion interpolation from one predeclared narrow timestamp window before requesting images. Use the timestamp index to isolate candidate row IDs, then read the selected metadata records. A range-backed read-only APSW VFS can execute index-assisted SQLite queries, but APSW is absent from the current Python environment. The standard-library probe already checks the index without a new dependency. The index does not include topic ID. A full-trajectory scan for motion-capture rows alone would visit many mixed table pages and requires its own budget. Bounded packet extraction should cap request count, transferred bytes and wall time and coalesce physically adjacent overflow pages only after validating SQLite links. [APSW VFS documentation](https://rogerbinns.github.io/apsw/vfs.html)

Independent camera poses remain a separate qualification gate. The Stanford paper used per-sequence hand-eye calibration and a dense LiDAR map, aligned stereo frames by capture timestamp and skipped motion-capture dropouts. No equivalent calibrated camera/LiDAR pose products were found among the released Zenodo files examined here. A later fixed physical test needs independently established marker-to-camera and LiDAR-to-camera geometry, reference depth coverage and uncertainty at our pose tolerance. [Stanford benchmark, LunaPolaris section](https://arxiv.org/html/2610.30774v1#S3.SS3.SSS4)

Run `python3 audit_lunapolaris_metadata_v104.py > evidence.json` from this directory to reproduce the exact metadata probe. It uses the Python standard library.
